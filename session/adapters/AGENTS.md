# session/adapters

Per-agent vocabulary: one adapter per CLI, tables and pure functions only.

## Invariants

Each entry is a rule, its why, and where it is pinned. Mechanism lives in the code.

### Agent Adapters

- Claude Code, Codex and Kimi Code are first-class: a change to one adapter's hook mapping re-captures that agent's fixtures with its `harness/probe-*-session.ts`, and the agent parity matrix fails any scenario row without a live fixture per agent reaching one outcome. Grok and custom agents stay best effort, outside the matrix.
- An adapter is TABLES and PURE FUNCTIONS: what varies between agent CLIs is vocabulary, and flags cannot express one. `resolveCommand` is lazy and cached per id, or a `require` costs a PATH lookup.
- Key on `capabilities`, never `adapter.id`, which rots once a third agent shares a behavior with the first. An UNDECLARED capability is absent.
- The Add Session agent picker and the card badge are adapter-driven and BINARY-GATED: `list-agents` probes each registered adapter's `resolveCommand` (cached per id), `decideAgentPicker` offers only the ones that resolve and hides itself for a single-agent install, and the badge shows a short label for a non-default agent only, so a Claude-Code-only machine looks unchanged (`public/session-card/agent-core.ts`). `glimmervoid doctor` prints the same per-agent resolution.
- A relay hook forwards the envelope UNTOUCHED and exits 0 whatever happened, since a hook that fails must never fail its turn. Field aliasing stays server-side.
- The relay target rides `GLIMMERVOID_HOOK_URL` in the spawn env, never argv: a command line is readable by any local process, and an env target leaves an installed hooks file inert unsupervised.
- Codex (`agent: "codex"`) declares every capability: snake_case payloads mapped by a table (`session/adapters/codex.ts`), live-verified on 0.163 by `harness/probe-codex-session.ts` into the `tests/fixtures/v2-codex-*` fixtures, hooks injected as `-c 'hooks.<Event>=...'` argv (the only form `exec resume` takes). Below 0.163.0, or with an unreadable version, only the five legacy events are injected, since older codex lacks the rest (`session/core/codex-version-core.ts`). Plan limits come from rollout `rate_limits`, not a statusLine relay. No `Notification` event is no gap: Claude maps its idle prompt to ready too, so a prose question ends the turn on both. A plan awaiting approval is read at Stop from the rollout (only the session's own file inside a Codex home, scanned backward to the turn's start), because the Stop payload carries no plan signal. Codex fires Stop only after SubagentStop, so a Stop held by an open subagent cannot occur.
- Grok uses an opt-in home hooks file inert without `GLIMMERVOID_HOOK_URL`; injection is refused when Claude settings in the cwd ancestry have hooks, never for the operator's own `~/.claude` (killed by `GROK_CLAUDE_HOOKS_ENABLED=false`), `Stop(end_turn)`, `StopFailure` and `StopCancelled` complete, subagent hooks plus camelCase `backgroundTasks` gate completion, titles never default ready (`session/adapters/grok.ts`).
- The codex hook-trust bypass is `projects[].codexBypassHookTrust`, config-file only, default OFF, and refused even when opted in if the cwd ancestry holds a `.codex/config.toml` that could contribute hooks or a `.codex/hooks.json` at all, skipping the Codex home exactly as Codex's own project-layer loader does. The bypass is not scoped to Glimmervoid's own hooks: it runs every hook the invocation loads (operator config PLUS repo-shipped PLUS agent-written), so it fails toward the title tier (`session/sessions.ts._decideHookTrustBypass`).
- The Codex supervision line rides `-c developer_instructions='''...'''`, a TOML literal string because the cmd.exe shim path tolerates no double quotes, and is withheld when the operator `config.toml` in the Codex home or the launch itself sets that key: a per-launch override replaces the operator's value outright. An unreadable config counts as set.
- A captured resume id is validated before it becomes argv: `RESUME_ID_RE` requires an alphanumeric first char (one shared definition), or a forged hook payload of `--dangerously-bypass-approvals-and-sandbox` would ride `args.push("resume", id)` as a flag (`session/core/auto-resume.ts`).
- `dangerouslySkipPermissions` on a codex card keeps the Codex sandbox: it maps to `-a never -s workspace-write`, never `--dangerously-bypass-approvals-and-sandbox`, so the same checkbox that only silences prompts on Claude does not buy an unrestricted, network-capable session on codex. One exception: under Glimmervoid's outer guardrails the Codex sandbox is switched off, since it cannot start inside one, and the outer guardrails is then the boundary.
- The codex title tier reads the WHOLE title against this session's cwd basename (`OscTitleSource.setContext`) and never emits a transition, anything unrecognized being `unknown`. A `quietUntilFirstPrompt` latch (with a `titleQuietFallbackMs` deadline) swallows codex's boot title spin that once flashed a fresh card COMPLETE. `-c check_for_update_on_startup=false` kills the blocking self-update prompt; a supervised session never self-updates.
- Kimi Code reads hooks only from `[[hooks]]` in the config.toml under KIMI_CODE_HOME, and the operator's file is never written, so every kimi session runs on one generated home whose config is the real one plus the hooks block and whose other entries link back to the real home; a home that cannot be built refuses the spawn rather than run kimi without hooks (`session/agent-home.ts`).
- Codex skips user-layer hooks without a `[hooks.state] trusted_hash`, and ignores `hooks.state` passed by `-c`, so a local codex session runs from a generated CODEX_HOME, built like the Kimi Code home, whose block trusts ONLY Glimmervoid's own hooks, by hashes `codex app-server hooks/list` computes (`session/codex-hook-trust.ts`); repo-shipped hooks stay untrusted, and an unreadable hash leaves the hooks untrusted and Sane YOLO reported off rather than refuse the spawn.
- Kimi subagent hooks carry no agent id and a subagent fires its own bare `Stop` before `SubagentStop`, so the subagent gate keys on the `Agent` tool call's `tool_call_id` (PreToolUse opens, PostToolUse closes), never on SubagentStart/SubagentStop (`harness/probe-kimi-session.ts`, `tests/fixtures/v2-kimi-subagent.jsonl`).
- Kimi `/clear` reports SessionStart `startup` with a new id, so once a prompt has run since spawn a startup naming another id counts as a clear; before any prompt it never replaces the saved conversation (`session/core/auto-resume.ts`).
- Kimi has no prompt argument and no flag to skip its "Trust this folder?" dialog, whose Enter means "Trust and continue", so the initial prompt is pasted and submitted only when kimi's own `workspace-trust` record for the cwd exists; Glimmervoid never answers that dialog (`session/adapters/kimi.ts`).
