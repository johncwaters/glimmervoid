# Ask

Run one question round and write its answers. Every stage asks through here.

Rounds are off unless the operator asks for them ("grill me", "ask me"); ending one early turns them off. With rounds off, ask nothing, the hand off included: research each question, close it on its recommendation as an `assumed` decision whose `evidence` cites the sources, take the named review gate or `gating-reviews`, then cut and build. A question whose sources disagree or whose choice cannot be undone stays open. A `critical` goal decides the same way.

1. Ask with your structured question tool (AskUserQuestion in Claude Code); without one, print the round as a numbered list with lettered options and wait for the reply. Ask up to four mutually independent questions, each offering two to four real alternatives with their costs. An option labelled `(change at the source)` goes first; otherwise the recommended one goes first. Mark the recommended one `(Recommended)` wherever it sits, with its reason. Recommend the option with the best design: a migration, extra files or a larger edit is a cost listed on that option, and the recommendation still goes to the best design. Every question shows its upstream, so the operator sees whether an option changes the source. An interface the repo owns, such as a schema, a contract or a tool's input, sits above every option that copes with what its callers send: changing it is the change-at-the-source option, and the code that option rewrites counts as the thing to change, with its current shape weighing nothing against the change.
2. Show what is being chosen. When an option is a type, signature, call graph, pseudocode, flow, or mockup, put it in the option's `preview`, or under the option in a plain-text round, so the alternatives sit side by side.
3. Write every answer into the graph right away. A chosen option or a settling free-text answer becomes a `decided` decision, or the chosen code of a design node, whether it closed a branch or a slice question, so a later challenge that undoes it shows at hand off. A partial answer records what it settled and returns as a narrower branch. A redirecting answer rewrites the goal, the non-goals, and the affected branches first.
